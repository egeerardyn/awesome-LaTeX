## Adding to this list

If you want something to be included on `awesome-LaTeX`, try to only add actual awesome stuff in your pull requests. After all, it's a curation, not a collection.

But **what is awesome?**

## Only awesome is awesome

Research if the stuff you're including is actually awesome. Put only stuff on the list you can personally recommend and rather leave stuff out than include too much.

## Comment on why something is awesome

Apart from suggesting a particular item, you should also inform your readers *why* it's on the list and how they will benefit from it.

## Inclusion criteria

These criteria apply to every new entry. The [pull request template](.github/pull_request_template.md) has a checklist for them.

- **Disclose affiliation.** If you wrote, maintain, work for or are paid by the project you are adding, say so in the pull request. Self-promotion is fine when it is disclosed.
- **Disclose AI use.** If AI was used to build the tool, or to write the pull request itself, say so and briefly say how. AI-generated tools and pull requests are welcome; pull requests that hide AI use are not and will be closed.
- **About 3 months of public history.** As a guideline, a project should have been publicly available and actively developed for at least 3 months before it is added. An exception is possible when nothing on the list covers what the tool does, or when there is real urgency for the LaTeX community to have it now rather than in a few months. Exceptions must be argued for in the pull request, and they remain the exception, not the rule. Pull requests that are too young are usually closed with an invitation to resubmit later.
- **Mark paid tools.** Commercial and freemium tools are welcome if they are LaTeX-specific, but the description must say so (e.g. `Freemium.` or `Paid ($30/yr, 7-day trial).`).
- **No duplicates.** Check the list for tools that already do the same thing, and explain in the pull request how yours differs.
- **Links must pass CI.** The link checker and `awesome-lint` must pass on your pull request.

## Guidelines

Please ensure your pull request adheres to the following guidelines:

- Search previous suggestions before making a new one, as yours may be a duplicate.
- Please only add/remove one (1) item per pull request.
- Please ensure your items are formatted consistently with the rest, e.g. as `[List Name](link) - Description.`, with a one-line description that starts with a capital letter and ends with a period.
- Link additions should be added to the bottom of the relevant category.
- New categories or improvements to the existing categorization are welcome.
- Please update the table of contents as needed.
- Check your spelling and grammar.
- Make sure your text editor is set to remove trailing whitespace.
- Self-promotion can be okay, but _only_ if you clearly state your involvement (see [Inclusion criteria](#inclusion-criteria)).
- The pull request and commit should have a useful title.

Finally, **thank you for your suggestions!**
